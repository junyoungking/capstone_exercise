# UI 디자인 규칙 (2026-10-21 확정)

시안 캔버스: Claude Design "운동 기록 앱 디자인 방향" (방향 요약 · 색과 글자 · 컴포넌트 규칙 · 세트 리포트(폰) · 실시간 두 번째 화면). 이 파일이 그 내용의 글 버전이다. 둘이 다르면 이 파일을 고치고 캔버스도 맞춘다.

## 방향

- 참고: Sportsbox AI.
  - 분위기는 이 파일이 정한다: 어두운 바탕, 측정값 중심, 형광 포인트 한 색.
  - 비교 화면 구성은 팀이 Sportsbox를 보고 만든 `feedback-ui` 브랜치를 따른다 (`docs/design.md` 6장): 포지션 버튼, 템포 패널, 범위 카드, 포지션 표, 진행도 그래프, 포지션 수정, 실패 화면, 3D 보기.
- 원칙 1. **숫자 먼저, 말은 나중.** 횟수·속도·시간은 크게 고정폭 숫자로. 문장은 숫자를 설명만 한다. 판정어(좋다/나쁘다/해야) 없음 (core/text의 금지어와 같다).
- 원칙 2. **색은 뜻이 있을 때만.** 바탕은 무채색, 장식 색과 그라데이션 없음.
- 원칙 3. **헬스장 거리에서 읽힘.** 실시간 화면은 2~3 m에서 본다. 횟수 숫자 200px 이상, 본문 대비 7:1 이상, 누르는 곳 48px 이상 (최소 44).

## 색 토큰

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--ground` | `#0E1116` | 화면 바탕 |
| `--surface` | `#161B22` | 카드 |
| `--raised` | `#1E2530` | 칩, 입력칸, 카드 안 칸 |
| `--line` | `#2A3340` | 테두리, 구분선 |
| `--text-1` | `#E8EDF3` | 본문 (ground 위 15:1) |
| `--text-2` | `#A9B4C2` | 설명, 라벨 (surface 위 8.9:1) |
| `--text-3` | `#8A97A8` | 아주 작은 보조 글 (ground 위 6:1 이상) |
| `--mine` / `--up` / `--primary` | `#C6F432` (라임) | 내 세트, 올리는 구간, 주 버튼. 위 글자는 `#0E1116` |
| `--ref` / `--down` | `#4F8CFF` (파랑) | 기준 영상, 내리는 구간 |
| `--pause` | `#6B7686` (회색) | 먼 점에서 멈춘 구간 |
| `--warn` | `#FF9F1C` (주황), 칩 바탕 `#2A1E0C`, 글자 `#FFB65C` | 확인 필요, 신뢰도 낮음 |

- 이 네 색 말고는 쓰지 않는다. 빨강/초록 대비 금지. 라임과 파랑은 밝기도 달라 색약도 구분된다.
- 내 세트와 기준 영상을 같은 그래프에 그릴 때 색만으로 나누지 않는다: 기준은 점선 테두리(또는 점선).
- 라임 숫자는 한 화면에 하나 (그 화면에서 가장 중요한 값).
- 속도 저하는 연속 막대 하나 (구간 색 나누지 않음, 파이프라인 탭 결정).

## 글자

- 한글·제목·본문: **Noto Sans KR** (400 / 500 / 700 / 900).
- 숫자: **JetBrains Mono** (500 / 700) — 고정폭이라 값이 바뀌어도 자리가 안 흔들린다. 단위(m/s, 초, cm, 회)는 Noto 13px `--text-2`로 숫자 옆.
- 크기: 제목 32/900 · 소제목 20/700 · 본문 16/400 (줄간격 1.6) · 라벨 13/400. 숫자: 핵심 72 · 카드 40 · 표 24 (폰 표 15). 실시간 횟수 300.

## 레이아웃

- 8px 격자. 화면 가장자리 16 (폰 390 폭) / 32 (두 번째 화면 1280×720).
- 카드 안쪽 24 (폰 16~20) · 카드 사이 16 · 같은 묶음 안 8~12.
- 모서리: 카드 16 · 칸·버튼 12 · 칩 999.
- 그림자 없음. 층은 1px `--line` 테두리와 바탕 단계로만 나눈다.

## 컴포넌트

| 컴포넌트 | 규칙 |
| --- | --- |
| 버튼 | 높이 48, 모서리 12. 주 버튼(라임 바탕) 화면당 1개. 보조는 투명 + 1px line, 그 아래는 글자만 |
| 종목 선택 | 세그먼트 (스쿼트 / 벤치프레스 / 데드리프트). 고른 칸만 raised 바탕 + 라임 글자. 칸 높이 44 |
| 측정값 칸 | 라벨(13, text-2) 위, 숫자(Mono) 크게, 단위 옆. raised 바탕, 모서리 12 |
| 템포 막대 | rep 한 줄 = 내림(파랑) → 멈춤(회색) → 올림(라임), 길이 = 시간. 오른쪽에 `내림 / 멈춤 / 올림` 초. 기준 영상 줄은 같은 색 점선 테두리 |
| 바 높이 그래프 | 라임 선, rep 구간은 raised 색 칸으로 뒤에 깔고 rep 번호 |
| 피드백 문장 카드 | 찾은 점만 카드로, 최대 3개 (core/text 규칙). 왼쪽 점 색: 기준 비교 파랑, 세트 안 라임. 괄호 안 값은 text-2. 판정 안 한 이유(none/skip)는 카드 없이 13px text-2 |
| 상태 칩 | 높이 32, 모서리 999, 앞에 8px 점. 추적 중(라임 점), 확인 필요(주황), 부분 rep 등(무채색) |
| rep 표 | 숫자 Mono, 오른쪽 정렬, 행 구분선 `#1E2530`. 가장 중요한 값 하나만 라임 |

## 화면

1. **세트 리포트 (폰 390)**: 머리(뒤로, 종목·세트, 날짜·중량, 원판 잡힌 프레임 칩) → 횟수 72 라임 + 속도 범위 → 측정값 칸 3개(깊이·내림·올림) → 바 높이 → 템포 → 피드백 → rep 표 → 아래 버튼 2개(기준 영상 고르기 / 다음 세트).
2. **실시간 두 번째 화면 (1280×720)**: 왼쪽 큰 횟수(300, 라임), 오른쪽 위 방금 rep 속도(72) + 가장 빠른 rep 대비 연속 막대, 오른쪽 아래 rep별 속도 막대(마지막만 라임).
3. **비교 리포트**: `feedback-ui`의 `web/report_template.html` 구성을 그대로 쓴다.
   - 순서: 세트 바 → rep 탭 → 사용자 영상과 기준 영상 나란히 → 현재 프레임 카드 → 타임라인 → 포지션 버튼·조작 → 목표 카드 → 템포 패널 → 포지션 표 → 진행도 그래프.
   - 데스크톱이 먼저이고, 650px 이하는 한 줄로 쌓인다.
   - 실패 화면은 `web/failure_template.html`이다.
4. 남은 화면 (아직 시안 없음): 업로드·처리 중, 세트 목록(기록), 기준 영상 고르기, 확인 필요 질문.

## feedback-ui와 맞출 것 (S5)

구성은 feedback-ui를 따르고, 색과 글자는 이 파일을 따른다.

| feedback-ui | 이 파일 |
| --- | --- |
| `--bg #191c23` / `--panel #242832` / `--inset #1c2029` / `--rule #3b4250` | `--ground` / `--surface` / `--raised` / `--line` |
| `--text #eeeef2` / `--dim #a3aaba` | `--text-1` / `--text-2` |
| 하강 `--down #2E5C8A` | `--down #4F8CFF` |
| 바닥 `--bottom #6B4E9E` | `--pause #6B7686` |
| 상승 `--up #2F7A55` | `--up #C6F432` (위 글자 `#0E1116`) |
| 선택 표시 `--accent #a7caff` | raised 바탕 + 라임 글자 (종목 선택과 같음) |
| 그래프 사용자 선 / 기준 선 | 사용자 라임 실선, 기준 파랑 점선, 기준 ± 임계값 띠는 raised |
| 글자: 시스템 글꼴 | Noto Sans KR, 숫자는 JetBrains Mono |
| 차이 크기: 노랑 `#E3A008` (k > 1), 빨강 `#D93F3F` (k > 1.5) | **결정 필요.** 권장안: 빨강은 쓰지 않는다. 범위 막대에서 기준 띠(파랑) 밖의 사용자 표시(라임) 위치로 보이고, k > 1은 굵은 숫자, k > 1.5는 칩을 채워서 2단계로 나눈다 |

## 접근성

- 진짜 `<button>`, `<a href>`, `<label>` 사용. 아이콘만 있는 버튼은 `aria-label`.
- 글자 대비 4.5:1 이상 (큰 글자 3:1). 위 토큰은 모두 통과.
- 색만으로 뜻을 전하지 않는다 (점선, 글자 라벨 함께).
