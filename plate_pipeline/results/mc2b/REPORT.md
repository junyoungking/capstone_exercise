# Mc2b 원판 고르기

## 상태

**완료 기준 미달로 `TrackCfg.plate_pick` 기본값을 계속 꺼 둔다.** 기존 Mc에서 정확했던 조건 안 영상의 횟수 회귀는 0개였지만, 전체 이벤트 정밀도는 .889 → .887로 떨어졌다. `stu10_11`의 Mc2 20회 개선도 유지되지 않았다. 켜서 실험하려면 `--plate-pick`, 명시적으로 끄려면 `--no-plate-pick`을 쓴다.

이 브랜치는 `origin/plate-pipeline`의 `94d8729`에서 시작했다. 기준 자료는 Mc의 61개·team9·분리 클립과 Mc2의 결과다. 이전 작업 트리 경로에서 사라진 Mc 원판 기록은 휴지통에 남아 있던 원본을 읽기 전용으로 사용했다. 새 분석·캡처는 이 작업 트리의 `eval_out/mc2b/`에 생성했다.

## 구현

검출은 기존 모델·임계값으로 프레임마다 한 번만 실행한다. 그 결과를 저장한 뒤 기존 선택과 KLT로 먼저 전체 영상을 추적한다. 이 원판 행 중 `used=true`인 `det`와 `det_low`의 중심 세로 좌표에서 5~95백분위 범위를 구해 측정된 상자 지름의 중앙값으로 나눈다. KLT 위치와 크기는 이동량 판정에 쓰지 않는다. 검출로 확인된 행이 3개 미만이면 움직임을 알 수 없는 것으로 처리해 기존 원판을 유지한다. 측정된 이동이 0.29 지름 이상이면 기존 원판을 유지하고, 그보다 작고 움직이는 확인 후보가 있을 때만 대안을 고른다.

기존 원판을 유지하더라도 연결된 약한 검출로 시작을 앞당길 수 있다. 첫 높은 점수에서 거꾸로 검출을 살피다가 상자가 화면 가장자리 1 px에 닿으면 멈춘다. 이 판정은 `box_angle_reliable`과 같은 `box_touches_edge` 함수를 공유하며, 원판의 폭/높이 비율에 대한 각도 신뢰도 검사는 별개다. 새 시작이나 대안이 필요한 경우에만 KLT를 한 번 더 실행한다. 시작과 선택이 같고 자세·타원 추가 처리가 없으면 기존 추적 행을 그대로 쓴다. 선택이 필요한 동안 별도의 진행 콜백으로 실제 검출과 추적을 보고한다.

검출 모델·임계값, KLT, rep 상태기계 숫자, `recover_early_back`은 바꾸지 않았다. 별도 자세나 타원 처리가 필요한 경로는 최종 원판에 대해서만 처리한다. 기준 영상 캐시는 기존과 같이 원판 선택 설정 및 소스 코드 변경에 따라 구분된다.

## Mc / Mc2 / Mc2b 비교

중간평가 61개와 team9 9개, 분리 클립 4개 중 같은 `stu8_7`을 한 번만 센 73개다. 이어 붙인 영상은 별도다. 원래 저장된 검출 전체가 각 프레임 10개 미만인 것을 Mc2에서 확인했으며, 이 검출을 원본 영상의 실제 KLT에 다시 넣었다. 모든 비교는 ±0.5초 완료 이벤트 매칭이다. team9 `stu3_64`는 총횟수 19회만 확정되어 이벤트 정답을 가진 8개 팀 영상만 P/R에 포함한다. 촬영 조건 구분 역시 Mc의 상자 비율·화면 검토 분류를 그대로 썼다.

Mc와 비교해 조건 안에서 **원래 총횟수가 맞던 영상의 회귀는 0개**다. `GB_S07_R12/14/20`은 모두 Mc의 1회를 되찾았다. 다만 R20은 Mc부터 GT 종료 시각과 0.5초를 넘게 차이나는 FP/FN이 있어 이벤트 기준으로 맞았다는 뜻은 아니다.

Mc2의 개선 유지 여부:

- `stu6_11_2/3`: 보관 원판 대신 움직이는 원판을 골라 0 → 4회와 0 → 1회를 유지했다.
- `LLK_S06_R32`: 같은 원판의 안전한 약한 검출을 앞당겨 0 → 1회와 정답 이벤트 일치를 유지했다.
- `squat_01`: 횟수 0 → 1회는 유지했으나 정답 11.042초, 예측 10.292초로 0.750초 차이가 난다. 이벤트로는 TP가 아닌 FP와 FN이 생겨 조건 안·중간 61·전체 정밀도가 Mc보다 낮아졌다.
- `stu10_11`: 기존 추적의 검출 기반 이동량이 **0.830 지름**이어서 요청한 규칙대로 기존 원판을 유지한다. Mc의 0회, Mc2의 대안 선택 20회, Mc2b의 0회다. Mc2가 쓴 첫 검출 묶음만의 이동량은 약 0.15 지름이라 서로 다른 결론이 났다. 이 개선 손실은 실제 추적 전체를 우선한다는 새 규칙과 충돌하므로 숨기거나 임계값을 바꿔 처리하지 않았다.

`user_clip_3` 첫 rep은 Mc2와 같이 누락된다. 이 작업은 Mc2에서 제시된 두 회귀 원인을 다루며, 미확인 원판을 새로 시작하는 규칙은 추가하지 않았다.

## 처리 시간

61.5초 연결 영상 1477프레임을 같은 머신에서 CPU ONNX 6스레드, OpenCV 1스레드로 순차 한 번씩 측정했다. Mc2는 **36.96초**, Mc2b는 **46.46초**로 9.49초(약 25.7%) 늘었다 (`timing.json`). 이 영상은 약한 검출로 시작이 앞당겨져 Mc2b에서 기존 추적 뒤 최종 추적을 추가로 실행한 사례다. 75개 중 선택과 시작이 같았던 51개는 이 추가 추적을 건너뛴다. 한 번씩 측정한 수치여서 실행 순서와 워밍업의 영향은 분리하지 못했다.

## 검증

75개 평가 항목 중 Mc와 고른 원판·시작 프레임이 같은 51개는 실제 KLT를 다시 실행한 행이 Mc 행과 같았다. 비교 직렬화가 저장 JSONL의 압축 해제 바이트와 같은 것도 확인했다. 나머지 24개는 선택이나 시작이 바뀌었다. 검출 기록을 재실행한 것이므로 모델을 새로 추론했을 때의 비결정성까지 증명하는 시험은 아니다.

합성 시험은 짧게 끊긴 후보 묶음과 실제로 움직이는 기존 원판, 정지한 기존 원판과 움직이는 대안, KLT만 움직이거나 검출이 부족한 경우, 1 px 경계에서의 역방향 중단을 확인한다. Mc2의 기존 선택 시험도 유지했다.

- `cd plate_pipeline && python -m pytest -q tests eval/midterm/test_metrics.py`: 211개 통과, Starlette 경고 1개.
- 저장소 루트 `python -m pytest -q tests/fb`: 235개 통과. PATH에는 Playwright에 포함된 node를 추가했다.
- 실제 `server.compare --plate-pick` 경로에서 `user_clip_3`을 분석했다. 원판 단계 진행률이 감소하지 않고 처리 프레임 수가 전체를 넘지 않는 것을 확인했다.
