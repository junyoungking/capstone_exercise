# M4b 원판 지름 확인과 각도 표시

브랜치 `integ/m4b-plate-size`, 기준 `integ/m4-ellipse` (`8f1767f`). 지름은 영상에서 직접 측정한 정답이 아니라 키·폰 화각·바와 사람 사이 거리 가정에서 역산한 제안이다. 실측 지름으로 확인해야 한다.

## 공식과 제안 기준

M2에서 H = (코–바닥 px / 0.92) × (D / 원판 상자 세로 px + 0.70 × cos(각도) / 초점 px)이므로 D = 원판 상자 세로 px × (0.92 × H / 코–바닥 px − 0.70 × cos(각도) / 초점 px)다. 단위는 m. 선택 리프터의 서 있는 프레임 중 원판 상자가 관측되고 화면 밖으로 잘리지 않은 프레임만 사용해 프레임별 역산의 중앙값을 쓴다. 해당 프레임이 없거나 양의 해가 없으면 추정하지 않는다. 내 영상은 입력 키가 있으면 그 키, 없으면 170 cm; 기준 영상은 항상 170 cm다. 범위는 각각 160·180 cm를 넣은 값이다. 상자 비가 0.95 이상 또는 한 프레임이라도 화면 끝에 닿으면 각도는 측정 어려움이며 cos=1로 둔다.

**제안 기준은 사용 지름과 추정 지름의 차이가 사용 지름의 30%를 초과할 때다.** GB/LLK/PB 30개를 작은 원판 후보, 나머지를 450 mm로 보이는 대조군으로 취급한 검증에서 추정 가능한 대조군 23개 중 잘못 제안 0개였다. 25%에서는 대조군 3개가 제안되어 30%를 택했다. 작은 원판 후보 30개 중 21개를 제안하고 9개를 놓쳤다. 이는 영상별 실측 지름이 없는 대리 분류 결과이며 실제 위양성·위음성의 확정 수가 아니다.

| 차이 기준 | 대조군 잘못 제안 / 추정 가능 | 작은 원판 후보 제안 / 30 |
|---:|---:|---:|
| 20% | 3 / 23 | 23 / 30 |
| 25% | 3 / 23 | 22 / 30 |
| 30% | 0 / 23 | 21 / 30 |
| 35% | 0 / 23 | 17 / 30 |
| 40% | 0 / 23 | 11 / 30 |

각도를 믿을 수 없는 추정 가능 42개에서 cos=1과 상자 비를 그대로 cos로 쓴 역산 지름의 절대 차이는 중앙값 0.0 mm, 최대 106.8 mm (benchpress/stu10_11.mp4)다. 이는 두 가정의 차이이지 정확도 정답이 아니다.

## 저장 결과 재계산

POST `/api/sessions/{id}/rescale`의 `plate_mm_user`, `plate_mm_ref`는 각각 선택적 양수이며 하나 이상 필요하다. 저장된 원판 rows와 2D pose를 읽어 신호, 상태기계, rep, 문장·판정 및 HTML을 다시 만든다. 기존 3D 좌표·분절을 재사용하며 검출·포즈·3D 모델은 실행하지 않는다. 두 지름을 독립 저장한다. 이전 JSON과 HTML은 `data/sessions/<id>/history/<version>/`에 보관하고 새 결과로 세션 및 기록의 횟수·최고 속도를 갱신한다. 완료 rep이 0개면 0회 화면을 표시하며 지름을 다시 바꿀 수 있다. 처리 실패 시 기존 결과는 유지한다.

실제 `GB_S01_R07` 단일 영상으로 450↔250 mm 네 번 요청했을 때 서버 전체 경과 0.069~0.103초, 계산 부분 0.020~0.051초였다. 각 요청의 기록은 `rescale_timing.json`에 있다. 1920×1080 실제 흐름에서 제안 버튼, 다시 계산 후 지름, 각도 측정 어려움과 콘솔 오류 0개를 확인했다.

캡처: `01_suggestion_and_angle.png`(450 mm·제안·각도 측정 어려움), `02_rescaled.png`(250 mm 재계산). `inspection_01.jpg`~`inspection_05.jpg`는 각각 PB 두 개, GB 한 개, LLK 두 개다. 파랑 상자는 원판 검출, 노랑은 상자 세로 픽셀, 연두는 2D 무릎–발목 길이이며 사람/원판의 실측 길이는 아니다. 직접 보면 원판이 정강이와 비슷하거나 작아 보이나 원근·자세와 가림의 영향을 받는다.

## 시험과 한계

- `cd plate_pipeline && python -m pytest -q tests eval/midterm/test_metrics.py`: 192 passed, Starlette 의존성 경고 1개. 루트 `python -m pytest -q tests/fb`: 235 passed. 합성 역산 왕복, 30% 경계, 잘림·각도, API 재계산/0회/이전 결과 보존 및 독립 지름을 포함한다.
- 실제 원판 지름과 키의 측정 정답이 없어 제안 정확도와 ROM의 절대 정확도는 검증되지 않았다. 170 cm 가정, 코–바닥 관측, 바 깊이·초점, 리프터 선택 및 화면 잘림은 모두 오차 요인이다. 위 대조군 분류도 영상상 추정이다.
- 완료 분석의 원판 행 또는 pose 파일이 없는 오래된 세션은 재계산할 수 없다. 독립 HTML은 제안을 보여 주지만 서버가 없으므로 버튼으로 저장 재계산할 수 없다.
