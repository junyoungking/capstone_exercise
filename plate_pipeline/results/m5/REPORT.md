# M5 자동 판단

## 상태

**원판 선택은 기본으로 켰지만, 자동 종목 확정의 완료 기준은 미달이다.** `plate_pick=true`와 완료 rep 0일 때 확인된 대안을 시험하는 규칙을 기본으로 켰다. Mc 대비 조건 안에서 기존 정답 횟수 회귀는 0개였고, `stu10_11`은 0 → 20회로 복구됐다.

사용자가 v40 ST-GCN+TCN 체크포인트가 없다고 확인했다. 실제 가중치 없이 분류기 출력을 만들지 않았다. 73개 영상 모두 자동 확정 대신 **종목 확인 필요**이며, 따라서 조건 안 확인 필요 10% 이하 기준은 충족하지 못했다. 선택한 종목은 사용자가 정한 값으로 기록하고, 원판 기록은 재사용한다. 벤치는 저장된 후보 선택 비교에서 다른 사람이 선택될 수 있을 때만 포즈를 다시 추출한다.

## 0. 원판 선택

검출은 프레임마다 한 번이다. 확인된 기존 후보의 안전한 약한 검출 시작점을 먼저 정하고 그 위치에서 곧바로 기존 KLT 추적을 한다. 화면 경계 1 px 중단 규칙은 유지한다. 기존 원판이 완료 rep 0이면 확인되고 0.29 지름 이상 움직인 후보를 최초 확인 프레임·점수×넓이 순으로 추적한다. 각 후보는 450 mm 고정으로 위·아래 쉬는 쪽을 각각 계산해 더 큰 완료 횟수를 사용한다. 처음 완료 rep이 나온 후보를 쓰고, 없으면 기존 원판을 유지한다. 사용자의 실제 원판 지름과 종목은 이 선택에 들어가지 않는다. 추가 KLT 추적은 대안 후보를 시도할 때만 수행한다. 자세·타원·콜백이 추가로 필요하면 저장된 원판 행을 읽으며 계산하고 KLT를 되풀이하지 않는다.

73개(61 + team9 9 + 내 분리 클립 4에서 중복 한 개 제거), 연결 영상은 별도다. Mc와 Mc2b의 동일 GT 및 ±0.5초 완료 이벤트 매칭을 썼다. team9 `stu3_64`의 종료 시각은 미완성이어서 이벤트 지표에서는 빠진다. 모델을 다시 추론하는 대신 Mc의 실제 검출을 보관한 행으로 실제 원본 영상에서 KLT를 재실행했다.

## 1. 종목 근거와 안전한 확인

원판 높이의 첫 13 cm 이동 방향과 초기 휴식 구간의 발·원판 위치를 함께 본다. 발은 화면 안, y ≤ 화면 높이의 0.97인 점만 쓰며 어깨·엉덩이·무릎·발목 순서를 확인한다. 초기 휴식 구간에 유효 관측이 5개 이상이어야 하고 처음 13 cm 이동한 뒤 바닥 근거를 고정한다. 이동 방향과 바닥 근거가 일치하고 같은 쉬는 쪽의 완료 rep이 있어야 쉬는 쪽을 낸다. 몸통은 휴식 및 rep 구간에서 어깨와 엉덩이 방향을 각각 모아 누움·섬이 일치할 때만 낸다. 상자 각도는 M4b와 같은 신뢰도·1 px 경계 검사를 통과할 때만 낸다.

v40 형식은 COCO17 관절, RTMPose **원래 점수**, 힙 중심·어깨-힙 길이 정규화, 8 Hz의 causal 표본, 8개 특징 채널과 32프레임 창이다. MP33 visibility는 `score / 0.6`에서 1로 잘리므로 역산하지 않고 선택된 사람의 원래 점수와 선택 리셋을 별도 저장한다. v40의 원본 특징 코드와 배열 단위로 일치하는 합성 시험을 만들었다. `V40_CHECKPOINT`가 제공되면 해당 구조를 읽어 rep 구간 창만 투표한다. 유효 체크포인트·점수·리셋이 없거나 근거가 엇갈리면 확인이 필요하다. 보정되지 않은 분류 점수는 화면에 퍼센트로 표시하지 않는다. 실험 코드는 입력 형식을 맞췄지만, 가중치가 없어 학습 당시 COCO17 RTMPose와 제품 Halpe26 RTMPose의 출력 분포 차이와 실제 분류 정확도는 검증하지 못했다.

모든 73개에서 실제 포즈를 추출했다. 쉼 판정이 나온 27개 중 27개가 정답이며 46개는 모름이다. 독립 근거의 정답/오답/모름은 바닥 **31/4/38**, 몸통 **30/4/39**다. 판정된 것만의 정확도는 각각 31/35, 30/34다. 분류기 투표는 0개라 정확도를 계산할 수 없다. 바닥 또는 몸통이 틀린 사례는 최종 종목으로 확정하지 않았다. 벤치 2개에서는 중립 포즈에서 스쿼트 후보가 나왔으므로 이 후보를 확정 종목으로 취급하면 안 된다. 세부 영상은 `auto_evaluation.json`, 집계는 `auto_summary.json`이다.

제품 자동 경로의 포즈 추출은 MP33 전체를 보존하며 `SideLock`을 호출하지 않는다. 직접 포즈를 붙이는 기존 `server.jobs` 경로의 `SideLock`은 사용자가 정한 종목을 그대로 쓴다.

중립 리프터 선택은 스쿼트식 손목·원판 선택이다. 비벤치는 기존 스쿼트·데드 선택 경로가 같고, 벤치 16개는 별도로 벤치 전용 포즈 선택도 추출해 비교했다. 5개에서 적어도 한 프레임의 몸통 중심이 정규화 화면 거리 0.1보다 달랐다: `stu10_11` 1117/1783, `stu8_7` 7/658, `test153` 300/300, `stu7_7` 8/149, `stu9_10` 703/1416 프레임. 이는 사람 차이의 지표이지 5개 모두 오선택이라는 정답은 아니다. 실제 프레임에서 `test153`, 동작 중 `stu10_11`, `stu9_10`은 중립 선택이 보조자를 고르는 장면을 확인했다. `images/lifter_choice.jpg`는 `stu10_11` 동작 중 비교다.

런타임에는 같은 후보들에 대해 벤치 선택이 중립 선택과 달라지는 프레임을 기록한다. 차이가 있거나 기록이 없는 경우 벤치를 고르면 포즈를 다시 추출하고, 모든 프레임에서 선택이 같으면 저장된 포즈를 쓴다. 종목 자동 확정도 선택 차이가 없는 경우에만 허용한다. 새 로직의 실제 `stu10_11` 검사에서는 1798프레임 중 95프레임에서 선택이 달라질 수 있었다 (`ambiguity_check.json`). 73개 근거 평가용 포즈는 이 기록을 추가하기 전에 추출했으므로, 73개 모두에서 새 기록 자체의 탐지율을 검증한 것으로 주장하지 않는다.

## 화면과 확인 후 재사용

업로드 기본은 자동이며 직접 고른 종목은 그대로 쓴다. 자동은 내 영상과 기준 영상을 각각 판단한다. 후보가 다르면 확인 화면과 리포트에서 차이를 알린다. 체크포인트가 없거나 근거가 부족하면 리포트 대신 종목 버튼을 표시한다. 확인 후 저장된 브라우저 영상·원판 행·포즈를 재사용하고 최종 종목으로 상태기계와 리포트를 다시 계산한다. 벤치 선택이 달라질 수 있는 경우에만 그 영상의 포즈를 다시 추출한다. 기록에는 최종 종목과 `exercise_source`를 저장한다.

실제 내 클립 1에서 자동 → 확인 필요 → 스쿼트 선택 → 리포트 → 운동 기록 흐름을 실행했다. 1920×1080과 1440×900에서 업로드·처리·확인·리포트·기록을 캡처했고 콘솔 오류는 0개였다. 대표 파일은 `images/upload_1920.png`, `images/confirm_1440.png`, `images/report_1920.png`; 나머지는 `eval_out/m5/browser/`에 있다. 확인 패널 버튼은 두 해상도에서 화면 안에 보였다. rep이 한 개일 때 속도 막대가 카드 너비를 거의 채우는 기존 배치는 다소 넓어 보인다. 73개 확인 필요 영상의 실제 프레임은 `eval_out/m5/auto_frames/`에 각각 저장했다.

같은 실영상을 내 영상과 기준 영상에 넣은 별도 시험에서도 두 판단이 각각 확인 대기로 들어갔고, 스쿼트 확인 후 두 결과는 각각 1회로 rep 배열이 같았다. 재개 시 저장 포즈를 재사용했다 (`ref_check.json`).

체크포인트가 없어 자동 확정된 실영상이 0개이므로 **자동 확정 결과와 수동 결과의 동등성은 검증할 수 없었다.** 별도로 위 클립에서 확인 후 스쿼트를 선택한 결과와 처음부터 수동 스쿼트를 선택한 결과의 rep 배열은 완전히 같았다 (`numeric_check.json`).

## 처리 시간과 시험

61.5초 연결 영상(1477프레임)을 같은 머신에서 CPU ONNX 6스레드로 순차 측정했다. 종목을 직접 지정한 Mc2b 전체는 **66.99초**(원판 32.84초, 포즈 32.65초)였다. M5 자동 경로는 확인 대기까지 **82.54초**, 스쿼트 선택 후 저장 자료로 마무리 **2.99초**, 계산 합계 **85.53초**였다. 사람의 선택 시간은 제외했다. 체크포인트가 없으므로 분류기 추론 시간도 포함되지 않는다. 각 한 번씩 측정한 값으로 워밍업·실행 순서의 영향을 분리하지 못한다 (`timing.json`, `timing_auto.json`).

- `cd plate_pipeline && python -m pytest -q tests eval/midterm/test_metrics.py`: 225개 통과, Starlette 경고 1개.
- 저장소 루트 `python -m pytest -q tests/fb`: 235개 통과. PATH에는 Playwright에 포함된 node를 추가했다.
- 원판 선택 기본값 변경 후 `python eval/m5/sim.py`의 합성 신호 360개 결과는 `results/mc/sim.json`과 전체가 같았다. 이 합성 시험은 검출·포즈를 모사하지 않는다.
- 브라우저 화면의 자동 분류 확률은 표시하지 않는다. `V40_CHECKPOINT`를 제공하기 전까지 조건 안 확인 필요 비율과 실제 분류기 정확도 기준은 미완료다.
