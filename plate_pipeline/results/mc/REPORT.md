# Mc 원판 기반 횟수 보강

## 결과와 범위

완료점 보정 `recover_early_back` 한 가지를 기본으로 켰다. 중복 영상을 한 번만 센 73개 영상 중 **이벤트 정답이 완전한 72개**에서 TP/FP/FN은 101/15/74 → 104/13/71, 정밀도 87.1% → 88.9%, 재현율 57.7% → 59.4%다. 총횟수가 맞는 영상은 57/73 → 58/73이다. 촬영 조건 안에서는 이벤트 정밀도 84.2% → 85.5%, 재현율 81.0% → 82.3%다. 기존에 총횟수가 맞던 영상이 틀려진 사례는 없다. **중간평가 61개는 결과가 바뀌지 않았다.**

기존 `plate-pipeline`의 M0·S1.5a·S1.5b 결정과 `results/midterm/view_tags.csv`를 따랐다. 평가 단위는 원판 `rep_values.back`이 있는 완료 rep이며 GT와 0.5초 이내의 순서 보존 최대 매칭이다. 원래 61개는 `gt_clock.csv`와 당시 `per_video.csv`의 모든 영상별 TP/FP/FN, 횟수에 일치하는 것을 먼저 확인했다. team9는 `eval/lists/team9.csv`의 재검수 횟수와 v40 `records.json`의 프레임 종료 라벨을 사용했고 원본 PTS와 첫 PTS 차이를 사용한다. `stu8_7`은 61개와 파일 SHA-256이 같으므로 전체에서는 중복 제거했다. 실제 4개 클립은 요청한 오프셋을 24 fps H.264로 따로 잘라 주어진 시각으로 평가했다. 원본 연결 영상은 편집 영상으로 분리했다.

**정답 한계:** `stu3_64`는 팀 재검수 19회이나 v40은 17회, 그중 완료 프레임이 유효한 것은 16회다. 빠진 세 시각을 추측하지 않았다. 따라서 team9의 9개 모두 횟수 오차를 집계하되 이벤트 지표는 8개에 한한다. 나머지 7개 team9 프레임 라벨은 파일명과 기록의 종목·횟수·프레임 범위를 대조했으나, 별도 라벨 원본 영상이 남아 있지 않아 바이트 동일성은 확인할 수 없다. GT가 있는 다른 72개 영상도 아래 실패 원인 중 일부는 신호와 썸네일로 판단한 가설이며, GT 자체의 오류로 확정한 것은 아니다.

촬영 범위는 `view_tags` 원판 상자 가로/세로 0.5 이상과 검토 이미지의 자막·편집 여부를 사용했다. 0.5는 이상적인 원의 약 60도에 대응하는 **대리 지표**이며 바 끝이 상자에 잡히면 실제 카메라 각도를 보장하지 않는다. 태그나 영상에서 판별이 어려운 경우 조건 밖으로 보수적으로 처리했다. 전체 영상의 20/50/80% 시점 화면을 `eval_out/mc/view_review/`에 만들었고, 자막이 순간적으로만 나오는 경우 등 범위 분류에는 재검토 여지가 있다.

## 고치기 전 실패 유형

아래는 73개에서 이벤트 정답이 있는 72개만 합산한 미매칭 **이벤트 수**다. 한 rep의 완료 시각이 0.5초 넘게 어긋나면 FN과 FP가 각각 하나씩 생긴다. 팀9 중복과 연결 영상은 제외했다. (마)는 상태기계 이후 완료점 선택의 조기/지연도 포함한다. 상세 영상·시각·근거와 불확실성은 `failures.json`에 있다.

| 유형 | 조건 안 FN | 조건 안 FP | 조건 밖 FN | 조건 밖 FP |
|---|---:|---:|---:|---:|
| (가) 검출/추적 누락 | 4 | 1 | 42 | 0 |
| (나) 처음부터 다른 원판 | 0 | 0 | 5 | 0 |
| (다) 중간에 원판 바뀜 | 0 | 0 | 0 | 0 |
| (라) KLT 밀림/크기 왜곡 | 0 | 0 | 0 | 0 |
| (마) 상태기계·완료점 | 3 | 3 | 3 | 2 |
| (바) 클립 경계 | 1 | 1 | 0 | 0 |
| (사) 자막·편집·연결 | 0 | 0 | 8 | 0 |
| (아) 라벨·완료 시각 재확인 | 7 | 7 | 1 | 1 |

조건 안의 `user_clip_2`에서는 복귀 도중 3 cm 넘는 일시 하락으로 첫 국소 최고점을 끝점으로 삼았다. 정답은 11.210초인데 이전 값은 9.435초다. 상태기계가 나중에 70% 복귀를 확인했다는 사실과 모순된다. `user_clip_3`은 초반 올바른 원판 후보가 낮은 점수여서 첫 4.6초가량 추적이 시작되지 않았다. 약한 후보를 무조건 시작하면 바닥 등 다른 물체를 고를 수 있어 이번에 검출 임계값은 바꾸지 않았다. `stu6_11_2/3`은 정적인 보관 원판을 선택했고 조건 밖 사례다. 데드의 일부 완료 시각은 라벨과 바닥 접촉 사이에 0.5초가 조금 넘는 차이가 있어 (아)로 남겼다.

분석 이미지는 75개 항목마다 `eval_out/mc/evidence/{midterm,team9,user_clip,edited}/`에 생성했다. 원 신호와 정리 신호, 녹색 GT, 빨간 예측, 각 미매칭 시간 전후 프레임을 함께 표시한다. 이벤트 정답이 미완성인 영상은 그 사실을 표시하고 샘플 프레임을 보여 준다. 결과 폴더에 남긴 대표 자료:

- `images/clip2_early_back.png`: 바가 실제로 복귀하기 전에 이전 완료점이 찍힌다.
- `images/clip3_missed_detection.png`: 첫 rep 구간의 추적이 비어 있다.
- `images/stored_plate.png`: 보관 원판의 평평한 신호와 실제 운동이 불일치한다.
- `images/team9_bench.png`: 후보 규칙으로 복구한 뒤쪽 완료점과 별도로 남는 27초 부근 불일치가 있다.
- `images/deadlift_gap.png`: 하강 후반의 추적 공백과 조기 완료점. 곡선의 공백 연결을 실제 검출로 해석하면 안 된다.

## 규칙

스쿼트·벤치에서 기존 완료점이 없거나 상태기계의 복귀 확정 시각보다 앞설 때만, 같은 연속 신호 구간에서 복귀 확정 이후의 실제 최고점과 기존 crossing 규칙으로 완료점을 다시 찾는다. 다음 rep 시작을 넘지 않고, 실제 far-out과 back crossing이 모두 있어야 하며 원판 공백이 극점에 걸린 rep은 건드리지 않는다. 복구 성공 시 ROM과 시간·속도도 같은 끝점으로 다시 계산한다. 진입 6 cm, 이동 13 cm, 복귀 70%, 튐·정지·부분 rep·리랙 등 상태기계 숫자는 바꾸지 않았다. KLT, 검출, 원판 선택도 바꾸지 않았다.

설정은 `core.config.SpeedCfg.recover_early_back`이며 `python -m server.compare ... --no-recover-early-back`, `python -m server.jobs ... --no-recover-early-back`, 또는 `python -m server.app --no-recover-early-back`으로 끌 수 있다. 참조 영상 캐시 키에 설정을 넣고, 재환산 시 저장된 설정을 유지한다. 규칙이 한 개이므로 개별 실행과 함께 켠 실행은 같다. 로컬 원판 기록을 재생했을 때 끈 결과의 세트 JSON 직렬화 바이트가 75/75 이전 저장값과 일치하며 원판 행은 변경하지 않았다. `variants.json`에 원판 행 SHA-256과 비교 결과가 있다. 이 비교는 검출을 새로 돌린 출력 전체 파일의 바이트 동등성 시험은 아니다.

## 합성 시험과 검증

`python eval/mc/sim.py`는 세 종목, 15/30/60 fps, 다섯 잡음 수준, 각 8개 시드의 360개 세트를 동일 입력으로 비교한다. 정확한 세트 수는 359/360 → 359/360, 극점 조건은 359/360 → 359/360이다. 이벤트 TP/FP/FN은 1545/365/526 → 1603/372/468, 정밀도 80.89% → 81.16%, 속도 MAE 0.04256 → 0.04250 m/s다. 기존에 이벤트가 완벽하던 세트에서 새로운 오차는 없었으나 일부 이미 틀린 합성 세트에서 FP가 늘었다. 합산 정밀도 상승이 모든 개별 조건의 개선을 보장하지 않는다. 조건별 결과는 `sim.json`, 시험 설명은 `sim/README.md`에 있다.

- 조기 최고점·없는 완료점 복구, 공백에서는 보정하지 않음, 끄기 호환성, 정상 신호 유지: `tests/test_mc_endpoint.py` 4개 통과.
- `cd plate_pipeline && python -m pytest -q tests eval/midterm/test_metrics.py`: 196개 통과, 기존 Starlette 경고 1개.
- 저장소 루트 `python -m pytest -q tests/fb`: 235개 통과.
- 실제 clip 2를 `python -m server.compare`로 분석해 완료 rep 1개와 `back=11.2455`를 확인했다.
- 재생·분류는 `python eval/mc/baseline.py`, `python eval/mc/variants.py`, `python eval/mc/evidence.py`, `python eval/mc/report_data.py`. 원 영상과 기존 분석 기록의 로컬 경로가 필요하다.

남은 우선순위는 조건 안 초기 검출 실패와 완료 시각 라벨의 독립 재검수다. team9 `stu3_64`의 19개 종료 시각이 확보되기 전까지 모든 이벤트의 FN/FP 유형 분류와 team9 전체 이벤트 지표는 완성됐다고 볼 수 없다.
